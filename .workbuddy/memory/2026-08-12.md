## 多架构(amd64 + arm64)镜像
- 背景:最初推的镜像是 arm64(Mac Apple Silicon);buildx docker-container 驱动下,buildkit 容器经代理访问 auth.docker.io 持续 Bad Gateway(宿主机 curl 正常,代理按来源分流),多平台 --push 无法完成
- 解决链路(全部走已验证可行路径):
  1. buildkitd.toml 配置 docker.io mirror = https://docker.m.daocloud.io → buildkit 拉基础镜像不经 auth.docker.io(buildx create --config)
  2. 单架构构建 + --load 到本地:amd64(buildx --platform linux/amd64)/ arm64(本机 docker build)
  3. docker push 两个单架构 tag(daemon 代理正常)
  4. docker buildx imagetools create 合并 manifest(注意:CLI 需显式 HTTPS_PROXY=http://127.0.0.1:7890;且要用无 mirror 的 builder,否则 URL 解析到加速器出错)
- 结果:ztshia/upstairs-reader:latest 与 :v1.0.0 均为 manifest list,含 linux/amd64 + linux/arm64(digest 6d12efd20a0a...)
- 仓库中额外保留 :amd64 / :arm64 两个单架构 tag
- builder 备忘:upstream-builder(docker-container + mirror)用于构建,desktop-linux 用于 imagetools
